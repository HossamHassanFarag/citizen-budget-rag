# موازنتي | Citizen Budget 2026/2027

**افهم موازنة مصر ببساطة** — تطبيق ويب تعليمي تفاعلي مبني على "موازنة المواطن" الرسمية
الصادرة عن وزارة المالية المصرية للعام المالي 2026/2027 (الإصدار الثالث عشر، أغسطس 2026).

مشروع مقدّم لمسابقة وزارة المالية المصرية لموازنة المواطن.

---

## 1. فكرة المشروع

الهدف ليس عرض أرقام الموازنة فقط، بل تحويلها من وثيقة رسمية طويلة إلى تجربة تفاعلية
يفهمها أي مواطن، خاصة الشباب، عبر: محتوى تعليمي، رسوم بيانية تفاعلية، فيديو شرح قصير،
شات بوت مبني على الوثيقة الرسمية فقط (RAG)، اختبار قصير، وقناة لرأي المواطن.

**كل رقم مالي في التطبيق مصدره موثّق (رقم الصفحة في الوثيقة الرسمية) ولا تُخترع أي أرقام.**

---

## 2. المزايا

- 🏠 صفحة رئيسية بأهم الأرقام الموثّقة مع مصدر كل رقم.
- 🎬 فيديو شرح قصير (يُوضع يدويًا في `assets/budget_explainer.mp4`).
- 📊 استكشاف تفاعلي للموازنة (Plotly): الإيرادات والمصروفات، مسار الدين، دعم النشاط
  الاقتصادي، الحماية الاجتماعية، الاستحقاق الدستوري للصحة والتعليم، مؤشرات الاقتصاد الكلي.
- 📚 مقالات تعليمية مبسطة (10 مواضيع).
- 🧑‍🤝‍🧑 قسم "ماذا تعني الموازنة للمواطن؟" حسب اهتمامات المواطن.
- 💬 شات بوت **يعمل بالكامل عبر واجهات سحابية مجانية (Google Gemini API)**: بدون تحميل أي
  نموذج محلي، وبدون الاعتماد على جهاز المستخدم أو خادم دائم — مناسب تمامًا لـ Streamlit
  Community Cloud.
- 🛡️ حماية صارمة من الهلوسة: الإجابات مبنية فقط على النص الرسمي المسترجع، والحسابات
  الرقمية تُنفَّذ بلغة Python وليس بواسطة النموذج.
- 📝 اختبار قصير (5 أسئلة) من بيانات موثقة.
- 🗳️ نظام ملاحظات بسيط (SQLite، بدون تسجيل دخول أو بيانات شخصية غير ضرورية).

## 3. حزمة التقنيات

| المكوّن | التقنية |
|---|---|
| اللغة | Python 3.11 (موصى به) |
| الواجهة | Streamlit |
| الرسوم البيانية | Plotly |
| استخراج PDF | PyMuPDF (fitz) |
| فهرس البحث الدلالي | مصفوفة NumPy في الذاكرة (بحث تشابه جيب التمام) — لا حاجة لـ ChromaDB مع ~181 جزء فقط |
| التضمين (Embeddings) | `gemini-embedding-001` عبر Google Gemini API (سحابي، متعدد اللغات، يدعم العربية) |
| نموذج اللغة | نموذج Gemini من عائلة Flash (افتراضيًا `gemini-2.5-flash`) عبر Google Gemini API |
| قاعدة بيانات الملاحظات | SQLite (تخزين مؤقت/غير دائم على Streamlit Cloud) |

لا يوجد React أو Node.js أو PHP، ولا بنية Frontend/Backend منفصلة.
لا يوجد Ollama، ولا نموذج محلي، ولا اعتماد على `localhost`، ولا تحميل نماذج بحجم غيغابايتات.

## 5. التثبيت المحلي

### أ) المتطلبات
- Python 3.11 (موصى به لهذا المشروع؛ يعمل أيضًا على 3.10+)
- مفتاح Google Gemini API مجاني من [Google AI Studio](https://aistudio.google.com/apikey)

### ب) خطوات التثبيت

```bash
git clone <repo-url>
cd citizen_budget

python -m venv .venv
source .venv/bin/activate        # على ويندوز: .venv\Scripts\activate

pip install -r requirements.txt
```

### ج) متغيرات البيئة

```bash
cp .env.example .env
```

عدّل `.env` وضع مفتاح `GEMINI_API_KEY` الخاص بك فيه. **لا تشارك هذا الملف ولا ترفعه على GitHub**
(محمي بالفعل عبر `.gitignore`).

### د) بناء فهرس التضمين (مرة واحدة، أو بعد تغيير `chunks.json`)

```bash
python scripts/build_embeddings.py
```

هذا يولّد `data/embeddings/embeddings.npz` و`data/embeddings/metadata.json`. ارفعهما على GitHub
حتى لا يحتاج التطبيق على Streamlit Cloud لاستدعاء واجهة Gemini API لتوليد التضمينات عند كل تشغيل
(انظر القسم 6).

## 6. استراتيجية التضمين والتخزين المؤقت (Caching)

المشروع يستخدم استراتيجية تخزين مؤقت على مستويين، مصمّمة خصيصًا لبيئة Streamlit Community
Cloud ذات التخزين المؤقت/غير الدائم:

1. **مستوى ثابت/مُراجع في الكود (مفضّل):** `data/embeddings/embeddings.npz` +
   `data/embeddings/metadata.json`. حجمها صغير جدًا (بضع مئات من الكيلوبايتات لـ 181 جزء)
   ويُنصح برفعها على GitHub. عند وجودها ومطابقتها للبيانات الحالية، **لا يستدعي التطبيق واجهة
   برمجة تطبيقات التضمين إطلاقًا عند بدء التشغيل**.
2. **مستوى وقت التشغيل (احتياطي):** `.cache/embeddings/`. يُستخدم فقط إذا كانت الملفات أعلاه
   غير موجودة أو غير متطابقة (مثلاً في بيئة تطوير محلية قبل تشغيل `build_embeddings.py`، أو بعد
   تعديل `chunks.json`). يُبنى مرة واحدة فقط لكل تشغيل للعملية (process)، ولا يُعاد بناؤه مع كل
   سؤال أو كل إعادة تحميل لصفحة Streamlit، بفضل `st.cache_resource`.

`data/chunks.json` يبقى دائمًا **مصدر الحقيقة الوحيد**. ملفات التضمين مُشتقة منه فقط: إذا لم تكن
موجودة أو كانت بصمتها (`chunks_hash`) أو بيانات النموذج/الأبعاد غير مطابقة، تُعاد بناؤها تلقائيًا
منه (وليس أبدًا العكس).

للتحقق من صحة `RAG_DISTANCE_THRESHOLD` بعد تغيير نموذج التضمين، شغّل:

```bash
python scripts/calibrate_threshold.py
```

## 8. أوضاع تشغيل الشات بوت

| الوضع | متى يعمل | السلوك |
|---|---|---|
| **الذكاء الاصطناعي الكامل** | `GEMINI_API_KEY` معرّف وصالح، وواجهة Gemini API تستجيب | إجابة مولّدة بواسطة Gemini، مبنية حصريًا على النص الرسمي المسترجع، مع ذكر المصدر ورقم الصفحة |
| **الاسترجاع فقط** | `GEMINI_API_KEY` غير معرّف، أو فشل استدعاء Gemini (حد استخدام، انقطاع مؤقت، ...) | يعرض التطبيق **النص الرسمي المسترجع مباشرة** من الوثيقة، بدون توليد شرح بالذكاء الاصطناعي |
| **غير موجود (Not Found)** | البحث الدلالي لم يجد سياقًا موثوقًا (المسافة > `RAG_DISTANCE_THRESHOLD`) | رسالة واضحة: "لم أجد معلومة موثوقة عن هذا السؤال..." |
| **خطأ** | فشل غير متوقع (مثل تعذر تجهيز فهرس البحث) | رسالة خطأ واضحة بالعربية، بدون كراش أو Stack Trace |

**ملاحظة حول عرض حالة المساعد:** مؤشر "حالة المساعد" في واجهة الشات بوت يتحقق فقط من وجود
`GEMINI_API_KEY` (بدون استدعاء فعلي لواجهة Gemini)، لتفادي استهلاك حصة الاستخدام المجاني في كل
مرة يفتح فيها المستخدم الصفحة. أي فشل فعلي عند الاستخدام الحقيقي يُعالج بلطف داخل `answer_question()`.

**لا يعتمد الشات بوت على أي بنية تحتية محلية** — لا Ollama، لا GPU، لا نموذج بحجم غيغابايتات. كل
من التضمين والتوليد يمران عبر Google Gemini API فقط.

## 9. حماية الدقة من الهلوسة (Hallucination Protection)

- الأرقام المالية المعروضة في الصفحة الرئيسية والرسوم البيانية والمقالات تأتي **حصريًا**
  من `data/budget.json`، وهو ملف تم التحقق من قيمه يدويًا مقابل النص الفعلي لكل صفحة في
  الوثيقة الرسمية (راجع حقل `page` و`source` في كل قيمة).
- الشات بوت لا يجيب على الأسئلة إلا من السياق المسترجع دلاليًا من `data/chunks.json` (عبر فهرس
  Gemini Embedding). إذا لم يُعثر على سياق موثوق، يظهر: **"المعلومة دي مش موجودة في البيانات
  الرسمية المتاحة عندي."**
- أسئلة الحساب الصريحة (مثل "احسب الفرق بين الإيرادات والمصروفات") تُحسب بلغة Python من
  `budget.json` مباشرة (`utils/rag.py::calculate_from_structured_data`)، وليس بواسطة النموذج.
- حد الثقة في البحث (`RAG_DISTANCE_THRESHOLD`) قابل للتعديل عبر `.env` / Streamlit Secrets،
  ويمكن معايرته عبر `scripts/calibrate_threshold.py`.
- تعليمات النظام (System Prompt) في `utils/rag.py` تمنع النموذج صراحة من اختراع أرقام أو
  استخدام معرفته العامة بدلًا من السياق الرسمي.

## 11. النشر على Streamlit Community Cloud

1. شغّل `python scripts/build_embeddings.py` محليًا (مرة واحدة) وتأكد من وجود
   `data/embeddings/embeddings.npz` و`data/embeddings/metadata.json`.
2. أنشئ مستودع GitHub وارفع المشروع إليه (تأكد أن `.env` غير مرفوع، وأن `data/feedback.db`
   غير مرفوع — كلاهما محميان تلقائيًا عبر `.gitignore`، بينما `data/embeddings/` **يُرفع عمدًا**).
3. اجعل المستودع عامًا (Public) إذا لزم الأمر لخطة Streamlit Cloud المجانية.
4. ادخل إلى [share.streamlit.io](https://share.streamlit.io) وسجّل الدخول عبر GitHub.
5. اختر "New app" ثم اختر المستودع والفرع (Branch).
6. حدد `app.py` كنقطة الدخول (Main file path)، و Python 3.11 إذا أُتيح خيار الإصدار.
7. من "Advanced settings → Secrets"، أضف (بصيغة TOML):
   ```toml
   GEMINI_API_KEY = "ضع_مفتاحك_هنا"
   # اختياري:
   # GEMINI_MODEL = "gemini-2.5-flash"
   # GEMINI_EMBEDDING_MODEL = "gemini-embedding-001"
   # GEMINI_EMBEDDING_DIM = "768"
   # RAG_DISTANCE_THRESHOLD = "0.55"
   ```
8. اضغط Deploy.
9. بعد اكتمال البناء، ستحصل على رابط عام بصيغة `https://<اسم-التطبيق>.streamlit.app`.

## 12. حدود معروفة (Known Limitations)

- **لم يتم اختبار الشات بوت مقابل واجهة Gemini API الحقيقية** أثناء إعداد هذا التعديل، لأن بيئة
  الإعداد لم تكن متصلة بالإنترنت. تم اختبار كل منطق الكود (تحميل البيانات، بناء/التحقق من صحة
  التخزين المؤقت، البحث بالتشابه، معالجة الأخطاء، سيناريوهات مفتاح API المفقود وفشل النموذج)
  باستخدام عملاء Gemini وهميين (mocks) تحاكي شكل الاستجابات الحقيقية. **يجب على الفريق، قبل
  النشر الفعلي:**
  1. تشغيل `python scripts/build_embeddings.py` بمفتاح API حقيقي والتأكد من نجاحه.
  2. تشغيل `python scripts/calibrate_threshold.py` والتحقق من أن `RAG_DISTANCE_THRESHOLD`
     الحالي (0.55) يفصل فعليًا بين الأسئلة ذات الصلة والأسئلة غير ذات الصلة، وتعديله عند الحاجة.
  3. تجربة الأسئلة في القسم 10 فعليًا والتأكد من جودة إجابات `gemini-2.5-flash`.
  4. مراجعة حدود الحصة المجانية الحالية لـ Gemini API (تتغيّر بين الحين والآخر) والتأكد أنها
     كافية للاستخدام المتوقع.
- بعض قيم الرسم البياني لمعدلات نمو المصروفات الأولية (صفحة 11) غير واضحة تمامًا في تخطيط
  الوثيقة الأصلية، وتم تركها `null` تحسبًا لعدم اليقين بدلاً من تخمينها.
- الفيديو التوضيحي (`assets/budget_explainer.mp4`) غير مُرفق ضمن هذا التسليم؛ يجب على
  الفريق إنتاجه وإضافته يدويًا. التطبيق يتعامل مع غيابه بلطف (رسالة تنبيه بدل عطل).
- `feedback.db` (SQLite) يُعاد إنشاؤه تلقائيًا من الصفر عند كل إعادة نشر/تشغيل على Streamlit
  Community Cloud (تخزين غير دائم بطبيعته). التطبيق يتعامل مع ذلك بشكل صحيح (`init_db()` تُنشئ
  الجداول إذا لم تكن موجودة)، لكن أي ملاحظات سابقة من المستخدمين ستُفقد بين عمليات النشر ما لم
  يُربط بقاعدة بيانات خارجية دائمة (خارج نطاق هذا التعديل).
